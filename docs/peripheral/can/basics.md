# CAN 基础知识

## 总线仲裁

CAN 总线空闲时，多个节点可能同时开始发送。各节点一边发送，一边在采样点读回总线。 [Microchip · CAN 协议机制](https://developerhelp.microchip.com/xwiki/bin/view/applications/can/overview/mechanisms/)

仲裁从标识符的最高位开始逐位比较。在仲裁期间，如果一个节点发出 `1` 却读到 `0`，它就判定自己输了，停止发送当前帧并转为接收。胜出的节点继续发送同一帧，已经发出的位仍然有效，这就是**无破坏性仲裁**。输掉的报文如果仍在发送队列里，会等总线再次空闲后重新竞争。同一帧格式的两个报文在 ID 不同时，**数值较小的 ID 优先**，因为它在第一个不同的位置发送的是 `0`。 [CiA · 经典 CAN](https://www.can-cia.org/can-knowledge/can-cc)

### 例子：`0x120` 和 `0x128` 同时发送

| 节点 | 11 位标准 ID（从高位到低位） | 在 `ID[3]` 发出的值 |
| --- | --- | --- |
| A · `0x120` | `0010010`**`0`**`000` | 显性 `0` |
| B · `0x128` | `0010010`**`1`**`000` | 隐性 `1` |

两个标识符的前 7 位相同。到了 `ID[3]`，总线呈现 A 发出的 `0`。B 读回 `0` 后转为接收，因此图中后续几位只有 A 在发送，B 的 TXD 保持隐性。下图截取了标识符的最后 6 位。

### 相同 ID 或不同帧格式怎么比较？

- **同一格式、同一 ID 的数据帧和远程帧**同时发送时，经典 CAN 数据帧的 RTR 位是显性 `0`，远程帧是隐性 `1`，所以数据帧胜出。
- **标准帧和扩展帧**的前 11 位相同时，标准帧胜出。标准数据帧在 RTR / SRR 的位置胜出，标准远程帧会继续比较到 IDE 位。 [Bosch · CAN 2.0 规范（Part B，Arbitration Field）](https://www.canlab.cz/sites/default/files/pages/download/Can2spec.pdf)

仲裁决定的是**总线空闲后哪一帧先发**。高优先级报文到达时，如果总线上已有一帧正在传输，它也要等这帧结束。想了解节点在哪一刻读回总线，可以接着看 [CAN 位时间参数](./bit-timing.md)。

## TX 电平与总线状态

CAN 控制器的 **TX（Transmit，发送端）** 输出数字电平，接到 CAN 收发器的 `TXD` 输入。高速 CAN 收发器在正常模式下按这个电平驱动总线。

- **TX 输出低电平（`0`）**。收发器把 CANH 和 CANL 驱动到显性状态，差分电压增大。
- **TX 输出高电平（`1`）**。收发器释放总线。只有所有节点都释放总线，总线才呈隐性。如果另一节点正在发送显性 `0`，总线上仍然是显性。

控制器通过收发器的 `RXD` 输出读回总线的实际状态，显性为低，隐性为高。因此同一时刻可能出现 **TX 为高、RX 为低**，这正是逐位仲裁中判定失败的条件。 [NXP · TJA1051 数据手册（表 4）](https://www.nxp.com/docs/en/data-sheet/TJA1051.pdf)
