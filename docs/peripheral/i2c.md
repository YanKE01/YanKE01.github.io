# I2C 总线

I2C（Inter-Integrated Circuit）是由 Philips（现 NXP）提出的一种同步、半双工、多主多从的串行通信总线，仅需两根信号线即可连接多个器件，广泛用于连接传感器、EEPROM、RTC、显示驱动等低速外设。

本文主要参考 NXP 官方文档 [*UM10204 I2C-bus specification and user manual*，Rev. 7.0（2021-10-01）](https://www.nxp.com/docs/en/user-guide/UM10204.pdf)。除速率模式一节另有说明外，以下讨论以标准模式、快速模式和快速模式增强（Fm+）为范围；UFm 使用不同的电气接口和传输规则。

## 概述

| 项目 | 说明 |
|---|---|
| 信号线 | SCL（时钟）、SDA（数据） |
| 通信方式 | 同步、半双工 |
| 拓扑 | 多主多从，器件通过地址区分 |
| 输出结构 | 开漏（Open-Drain），需外接上拉电阻 |
| 典型速率 | 100 kbit/s、400 kbit/s、1 Mbit/s |

一帧典型的数据传输格式如下：

```
S | 从机地址(7 bit) | R/W | ACK | 数据(8 bit) | ACK | ... | 数据(8 bit) | ACK/NACK | P
```

## Q: I2C 总线由哪几根信号线组成？各自的作用是什么？

I2C 只有两根信号线：

- **SCL（Serial Clock）**：时钟线，通常由主机产生。
- **SDA（Serial Data）**：数据线，双向传输地址与数据。

两根线通常采用开漏（或开集电极）结构，需要分别上拉到合适的电源电压。总线空闲时，SCL 与 SDA 都保持高电平。两根信号线之外，器件还需要共同的电位参考，通常为共地连接。

## Q: I2C 为什么采用开漏输出并需要上拉电阻？

开漏输出只能主动将信号线拉低，无法主动输出高电平，高电平由上拉电阻提供。这种设计带来以下好处：

1. **线与（Wired-AND）特性**：任一器件拉低，总线即为低电平。这是多主机仲裁、时钟同步和时钟拉伸得以实现的基础。
2. **避免总线冲突造成短路**：若采用推挽输出，一个器件输出高、另一个输出低时会形成电源到地的直通电流，而开漏结构不存在这一问题。
3. **便于电平兼容**：可在满足所有器件输入阈值、引脚耐压和掉电特性的前提下选择上拉电压；若无法同时满足，则需要电平转换电路。开漏输出本身不代表引脚可以承受任意上拉电压。

## Q: I2C 的起始条件（START）和停止条件（STOP）是如何定义的？

- **起始条件 S**：SCL 为高电平时，SDA 由高变低。
- **停止条件 P**：SCL 为高电平时，SDA 由低变高。

```wavedrom
{
  signal: [
    { name: 'SCL', wave: '1.0.1.', node: '.A...C' },
    { name: 'SDA', wave: '10...1', node: '.B...D' },
  ],
  edge: ['A-B START', 'C-D STOP'],
  config: { hscale: 2 },
}
```

起始与停止条件总是由主机产生。在正常的数据传输中，**SDA 只允许在 SCL 为低电平时变化**，SCL 为高电平期间 SDA 必须保持稳定；因此 SCL 高电平期间 SDA 的跳变只会被识别为起始或停止条件。

## Q: 什么是重复起始条件（Repeated START）？有什么用途？

重复起始条件（Sr）是指主机在**不发送停止条件**的情况下再次发出起始条件。其电气特征与普通起始条件相同。

主要用途是在不释放总线的前提下切换传输方向或访问对象。最典型的场景是**读取从机的某个寄存器**：先以写方式发送寄存器地址，再通过 Sr 切换为读方式读取数据。由于期间总线未被释放，其他主机无法插入，从而保证了操作的完整性。

**波形与产生过程**：下图为发送完寄存器地址、收到从机 ACK 之后，主机产生 Sr 并开始发送读地址的过程。

```wavedrom
{
  signal: [
    { name: 'SCL', wave: '101..01', node: '...S...' },
    { name: 'SDA', wave: '51.0.3.', node: '...T...', data: ['ACK', 'A6'] },
    { node: '..AB...' },
    { node: '...C.D.' },
  ],
  edge: ['S-T Sr', 'A<->B tSU;STA', 'C<->D tHD;STA'],
  config: { hscale: 2 },
}
```

1. 从机在第 9 个时钟周期回复 ACK，此时 SDA 为低电平；
2. SCL 变低后，从机释放 SDA，主机也保持 SDA 释放，SDA 被上拉为**高电平**；
3. 主机释放 SCL，并检测其实际变高（可能需要等待时钟拉伸）；
4. SCL 保持高电平至少 **tSU;STA** 后，主机拉低 SDA，形成重复起始条件 Sr；
5. SDA 保持低电平至少 **tHD;STA** 后，主机拉低 SCL，随后开始发送 `从机地址 + R`。

第 2 步是关键：**SDA 必须在 SCL 变高之前就已经是高电平**。如果 SCL 变高时 SDA 仍为低电平，随后 SDA 的上升会被识别为**停止条件**，而不是重复起始条件。

| 参数 | 含义 | 标准模式 | 快速模式 | 快速模式增强 |
|---|---|---|---|---|
| tSU;STA | 重复起始条件建立时间（最小） | 4.7 µs | 0.6 µs | 0.26 µs |
| tHD;STA | （重复）起始条件保持时间（最小） | 4.0 µs | 0.6 µs | 0.26 µs |

::: tip Sr 与"先 STOP 再 START"的区别
两者都能开始一次新的传输，但发送 STOP 后总线即被释放，其他主机可能在 STOP 与下一个 START 之间抢占总线；部分从机还会在收到 STOP 后复位内部状态（例如寄存器指针）。使用 Sr 则总线始终被当前主机占用，保证了"写寄存器地址 + 读数据"这一组合操作的原子性。
:::

## Q: I2C 的 ACK 与 NACK 是如何产生的？

每传输一个字节（8 bit）后，紧跟第 9 个时钟周期用于应答：

- **ACK**：发送方释放 SDA，接收方在第 9 个时钟的低电平期间将 SDA **拉低**，并在高电平期间保持稳定。
- **NACK**：发送方与接收方都释放 SDA，第 9 个时钟高电平期间 SDA 由上拉保持为**高电平**。

第 9 个时钟仍由主机产生，应答位也必须满足数据建立与保持时间。

出现 NACK 的常见原因：

- 总线上不存在该地址的从机；
- 从机正忙，无法接收或处理；
- 从机收到了无法识别的数据或命令；
- 从机无法再接收更多数据；
- 主机作为接收方时，用 NACK 通知从机**这是最后一个字节**，随后主机发送停止条件或重复起始条件。

## Q: I2C 的 7 位地址是如何发送的？R/W 位的含义是什么？

起始条件之后的第一个字节由 **7 位从机地址 + 1 位读写方向位** 组成，高位先发：

| Bit 7 ~ Bit 1 | Bit 0 |
|---|---|
| 7 位从机地址 | R/W |

- **R/W = 0**：写，主机向从机发送数据。
- **R/W = 1**：读，主机从从机读取数据。

下图为主机发送地址字节的完整波形（以写操作为例）：起始条件之后依次发送 A6 ~ A0 与 R/W 位，第 9 个时钟周期由从机应答，最后主机发送停止条件。

图中箭头标出了每个 SCL 上升沿，作为采样位置的示意；规范约束的是数据有效窗口与建立、保持时间，并不要求所有器件都在同一瞬间采样（详见下一题）。彩色数据块表示位的有效区间，不表示实际高低电平；本例 R/W = 0、ACK = 0。可以看出：

- **SDA 只在 SCL 为低电平时变化**（每个数据块的边界都位于 SCL 低电平期间）；
- **SCL 为高电平期间 SDA 保持稳定**，接收方在此期间读取 SDA；
- 唯一的例外是起始条件 S 与停止条件 P，它们正是通过在 SCL 高电平期间改变 SDA 来定义的。

```wavedrom
{
  signal: [
    { name: 'SCL', wave: '1...01010101010101010101.....', node: '..S..A.B.C.D.E.F.G.H.I...T...' },
    { name: 'SDA', wave: '1.0.3.3.3.3.3.3.3.4.5.0..1...', node: '..U..J.K.L.M.N.O.P.Q.R...V...',
      data: ['A6', 'A5', 'A4', 'A3', 'A2', 'A1', 'A0', 'R/W', 'ACK'] },
  ],
  edge: ['S-U S', 'T-V P', 'A->J', 'B->K', 'C->L', 'D->M', 'E->N', 'F->O', 'G->P', 'H->Q', 'I->R'],
  config: { skin: 'narrow' },
}
```

例如从机地址为 `0x50`，则写操作发送的字节为 `0xA0`，读操作为 `0xA1`。查阅芯片手册时需要注意，有的手册给出的是 7 位地址，有的给出的是包含 R/W 位的 8 位地址。

::: tip 保留地址
7 位地址中，`0000 XXX` 与 `1111 XXX` 两组被协议保留。例如，地址 `0x00` 配合 R/W = 0 表示通用呼叫（General Call），仅由支持该功能的器件响应；同一地址配合 R/W = 1 是 START byte，不是广播读。`1111 0XX` 用作 10 位地址的前缀。
:::

## Q: I2C 的 SDA 在什么时刻被采样？建立时间与保持时间有什么要求？

I2C 规范对数据有效性的规定是：**SCL 为高电平期间，SDA 必须保持稳定；SDA 只能在 SCL 为低电平期间变化**。由此可以得到一个完整数据位的过程：

1. **SCL 下降沿之后**：发送方在 SCL 低电平期间改变 SDA，输出新的数据位；
2. **SCL 上升沿之前**：SDA 必须提前稳定一段时间，即**数据建立时间 tSU;DAT**；
3. **SCL 高电平期间**：SDA 保持不变，接收方在此期间读取 SDA。实际器件通常在 **SCL 上升沿**或高电平期间完成采样；
4. **SCL 下降沿之后**：SDA 还需要保持一段时间才能变化，即**数据保持时间 tHD;DAT**，随后进入下一个数据位。

下图为单个数据位的放大时序，箭头 sample 仅示意一种采样位置，不规定器件内部的采样实现：

```wavedrom
{
  signal: [
    { name: 'SCL', wave: '10.1.0.', node: '...S...' },
    { name: 'SDA', wave: '2.3...5', node: '...T...', data: ['bit n-1', 'bit n', 'bit n+1'] },
    { node: '.AB..EF' },
    { node: '..CD...' },
  ],
  edge: ['S->T sample', 'A<->B tHD;DAT', 'E<->F tHD;DAT', 'C<->D tSU;DAT'],
  config: { hscale: 2 },
}
```

规范中与数据采样相关的主要时序参数如下：

| 参数 | 含义 | 标准模式 | 快速模式 | 快速模式增强 |
|---|---|---|---|---|
| tLOW | SCL 低电平时间（最小） | 4.7 µs | 1.3 µs | 0.5 µs |
| tHIGH | SCL 高电平时间（最小） | 4.0 µs | 0.6 µs | 0.26 µs |
| tSU;DAT | 数据建立时间（最小） | 250 ns | 100 ns | 50 ns |
| tHD;DAT | 数据保持时间（最小） | 0 ns | 0 ns | 0 ns |

**需要注意的几点**：

- **保持时间最小值为 0，不代表 SDA 可以与 SCL 任意同时翻转**：Rev. 7.0 表 11 注 [2] 要求，SCL 下降到 **0.3 VDD 以下**后，SDA 才能进入 0.3 VDD ~ 0.7 VDD 的不确定区间。无法检测 SCL 下降沿的主机应根据实际下降时间安排 SDA 延迟，不能将旧版常见的 **300 ns** 表述直接当作各模式统一的固定延迟。
- **上升时间会挤占建立时间**：SDA 由低变高时依靠上拉电阻缓慢充电，上升过程占用了 SCL 低电平期间的时间。若上升时间过长，SDA 可能在 SCL 上升沿到来时仍未达到 VIH，导致采样错误（参见"上升时间过长"一题）。
- **协议规定有效窗口，采样实现由器件决定**：SCL 高电平期间 SDA 的有效下降沿或上升沿分别表示 START 或 STOP；不能依赖输入滤波去掩盖违反时序的数据跳变。

## Q: 主机读取从机某个寄存器的完整时序是怎样的？

以支持连续读取、使用单字节寄存器地址的从机为例，读取从 `reg` 开始的 N 个字节（N ≥ 1）。寄存器地址宽度、自增行为和是否要求 Sr 均由芯片手册规定，I2C 本身不定义寄存器协议：

```
S | Addr+W | A | reg | A | Sr | Addr+R | A | Data1 | A | ... | DataN | NA | P
```

其中 `A` 为 ACK，`NA` 为 NACK。应答遵循**谁接收、谁应答**的原则，各应答位的发送方如下：

| 应答位置 | 发送方 | 含义 |
|---|---|---|
| `Addr+W` 之后 | 从机 | 确认地址匹配 |
| `reg` 之后 | 从机 | 确认收到寄存器地址 |
| `Addr+R` 之后 | 从机 | 确认地址匹配，此后数据位由从机发送 |
| `Data1` ~ `DataN-1` 之后 | 主机（ACK） | 通知从机继续发送 |
| `DataN` 之后 | 主机（NACK） | 通知从机传输结束，释放 SDA |

需要注意，读操作中**地址字节的应答仍由从机发出**，因为此时发送方是主机；从机回复该 ACK 之后，数据传输方向才发生反转。

1. 主机发送起始条件 **S**；
2. 发送从机地址 + 写位（W），从机应答 ACK；
3. 发送寄存器地址 `reg`，从机应答 ACK；
4. 主机发送重复起始条件 **Sr**；
5. 发送从机地址 + 读位（R），从机应答 ACK；
6. 从机依次发送数据，主机对前 N-1 个字节回复 ACK；
7. 主机对最后一个字节回复 **NACK**，通知从机停止发送；
8. 主机发送停止条件 **P**。

## Q: I2C 读操作的最后一个字节为什么要回复 NACK？

I2C 基础传输格式**没有长度字段**，主机根据芯片协议和应用需求决定何时结束读取，例如读取 2 字节温度值或从 EEPROM 连续读取 64 字节。对于支持连续读取的从机，主机持续提供时钟并回复 ACK 表示继续读取；超出有效范围后的返回值或地址回绕行为由器件定义。

在读操作中，SDA 由从机驱动。每个字节结束后，从机根据第 9 个时钟周期的应答决定下一步：

- **主机回复 ACK**：从机认为主机还需要数据，在第 9 个时钟的下降沿之后、下一位的低电平阶段准备后续数据；
- **主机回复 NACK**：从机得知传输结束，**释放 SDA**。

停止条件要求主机在 SCL 为高电平时使 SDA 由低变高，**前提是主机能够控制 SDA**。若最后一个字节回复的是 ACK，从机已开始发送下一位；若该位恰好为 `0`，SDA 将被从机拉低，主机无法产生停止条件，总线可能因此卡死。

因此，读操作的正确结尾为：

```
... | DataN-1 | A | DataN | NA | P
```

NACK 之后也可以发送重复起始条件 Sr，继续下一次传输。

::: tip 写操作与读操作的区别
写操作中 SDA 由主机驱动，主机发送完最后一个字节并收到从机的 ACK 后，可以直接发送停止条件，无需额外处理。写操作中的 NACK 由**从机**发出，表示其无法继续接收（设备忙、地址不存在或数据无效等）。
:::

::: info SMBus 块读
在 SMBus 的块读（Block Read）中，从机会先发送一个字节说明后续数据的长度，主机据此读取，并同样在最后一个字节回复 NACK。此时长度由从机告知，但结束方式不变。
:::

## Q: I2C 常见的速率模式有哪些？

| 模式 | 最高速率 | 说明 |
|---|---|---|
| 标准模式（Standard-mode） | 100 kbit/s | 最早定义，兼容性最好 |
| 快速模式（Fast-mode） | 400 kbit/s | 常见外设模式 |
| 快速模式增强（Fast-mode Plus） | 1 Mbit/s | 驱动能力更强 |
| 高速模式（High-speed mode） | 3.4 Mbit/s | 主从双方均须支持 Hs-mode，以主机码进入高速阶段 |
| 超快速模式（Ultra Fast-mode） | 5 Mbit/s | 单向传输，USCL/USDA 推挽输出；第 9 位固定为高、无应答，无仲裁和时钟拉伸 |

实际可用速率受总线电容、上拉电路和器件能力共同限制。普通标准/快速/Fm+ 混接总线应满足所有连接器件的模式与时序要求；Hs-mode 有专门的进入和混接规则，不能只提高 SCL 频率。UFm 不能直接混接到普通双向 I2C 总线上。

## Q: 上拉电阻的阻值应如何选择？

上拉电阻的取值需要在**功耗/驱动能力**与**上升时间**之间折中：

- **最小值**由器件的灌电流能力决定，阻值过小会导致低电平无法被拉到足够低：

  ```
  Rp(min) = (VDD - VOL(max)) / IOL
  ```

  VDD 指上拉电源电压；VOL(max) 与 IOL 应取所有可能拉低该线的器件在实际供电条件下保证的指标。对常见 VDD > 2 V 的标准/快速模式器件，可用 VOL(max) = 0.4 V、IOL = 3 mA 作示例；低电压器件、Fm+ 器件或特殊端口需查其数据手册。

- **最大值**由上升时间要求和总线电容决定，阻值过大会导致上升沿过缓：

  ```
  Rp(max) = tr / (0.8473 × Cb)
  ```

  其中 tr 取容许的最大上升时间：标准模式 1000 ns、快速模式 300 ns、Fm+ 120 ns；Cb 为每根总线的电容。规范表列电容上限分别为 400 pF、400 pF、550 pF，实际还需满足工作电压、频率与时序条件。

以 3.3 V、快速模式、总线电容 100 pF 为例：Rp(min) ≈ 967 Ω，Rp(max) ≈ 3.5 kΩ。工程上常用 **4.7 kΩ（100 kHz）** 和 **2.2 kΩ（400 kHz）** 作为初始值，再结合实测波形调整。

这些公式针对电阻上拉的近似 RC 模型，推导见 TI [SLVA689《I2C Bus Pullup Resistor Calculation》](https://www.ti.com/lit/an/slva689/slva689.pdf)。多个模块自带的上拉电阻会并联，应按等效阻值计算；若 Rp(min) > Rp(max)，则无法只靠选电阻满足要求，需要降低电容、调整速率或改变上拉方案。

## Q: I2C 信号上升时间过长会导致什么问题？如何排查和解决？

**现象**：用示波器观察 SCL、SDA，上升沿不是陡峭的方波，而是缓慢爬升的圆弧（俗称"鲨鱼鳍"波形）；下降沿则依然陡峭。

**定义与规范要求**：I2C 的上升时间 tr 指信号从 **0.3 VDD 上升到 0.7 VDD** 所需的时间，即从 VIL 阈值到 VIH 阈值。规范规定的最大值如下：

| 模式 | tr 最大值 | 总线电容 Cb 最大值 |
|---|---|---|
| 标准模式 | 1000 ns | 400 pF |
| 快速模式 | 300 ns | 400 pF |
| 快速模式增强 | 120 ns | 550 pF |

**根本原因**：在仅使用电阻上拉的开漏总线上，下降沿由器件内部的 MOS 管主动拉低；上升沿则依靠上拉电阻 Rp 对总线电容 Cb 充电，近似为 RC 过程（有源上拉不适用此简化模型）：

```
tr = 0.8473 × Rp × Cb
```

因此上升时间过长，本质上是 **Rp 过大**或 **Cb 过大**。常见的具体原因有：

- 上拉电阻取值过大，或**仅依靠 MCU 内部上拉**（通常为 30 kΩ ~ 50 kΩ，远大于 I2C 所需）；
- 总线上挂载的器件过多，输入电容逐项累加；规范表列的引脚电容上限为 10 pF，实际取值应查器件手册；
- 走线或连接线过长，例如通过排线、杜邦线连接外部模块；
- 总线上串入了 ESD 保护器件、电平转换电路等，引入额外电容。

**带来的问题**：

1. **采样错误**：SCL 变高时 SDA 尚未上升到 VIH，从机可能将 `1` 误读为 `0`，表现为地址无应答（NACK）、读写数据随机出错；
2. **建立时间不足**：SDA 的上升过程占用了数据建立时间 tSU;DAT（标准模式 250 ns，快速模式 100 ns）；
3. **实际速率下降**：部分主机在释放 SCL 后会等待其真正变为高电平，较慢的上升沿会被当作时钟拉伸处理，导致实际 SCL 频率低于设定值；
4. **抗干扰能力下降**：信号在阈值附近停留时间变长，更容易受噪声影响产生误判。

**排查方法**：

- 用示波器测量 SCL、SDA 从 30% 到 70% VDD 的时间，与规范值对比；
- 示波器探头使用**短接地弹簧**，并计入探头电容；带宽应按待测边沿的上升/下降时间选择，不能只取 SCL 频率的 10 倍。测量系统自身的上升时间应明显快于被测边沿：对常见的高斯响应示波器，其上升时间约为 0.35 / 带宽（例如 100 MHz 约 3.5 ns）；
- 估算总线电容：Cb ≈ tr / (0.8473 × Rp)，判断是电阻问题还是电容问题。

**解决方法**（按优先级）：

1. **减小上拉电阻**：不能仅用 MCU 内部上拉；在满足 Rp(min) 的前提下适当减小阻值（参见上一题）；
2. **降低总线电容**：缩短走线、减少挂载器件，必要时用 I2C 多路复用器（如 TCA9548A）断开未使用的支路；已选通支路的电容仍需计入；
3. **降低通信速率**：从快速模式降到标准模式，tr 的容许上限从 300 ns 放宽到 1000 ns；
4. **使用总线缓冲器或上升沿加速器**：如 PCA9515 等总线缓冲器可隔离两侧电容；LTC4311 等上升沿加速器在检测到上升沿时提供额外的上拉电流；长距离传输可使用 P82B715、PCA9600 等专用驱动器。

例如：Rp = 4.7 kΩ、Cb = 200 pF 时，tr = 0.8473 × 4.7 kΩ × 200 pF ≈ 796 ns，满足标准模式（≤ 1000 ns），但远超快速模式的 300 ns。若要运行在 400 kHz，需要将上拉电阻减小到约 1.77 kΩ 以下（例如选用 1.5 kΩ），或设法降低总线电容。

## Q: I2C 的 SCL、SDA 出现上冲、下冲或振铃，原因是什么？如何处理？

**现象**：示波器上看到信号边沿之后出现超过 VDD 的尖峰（**上冲**，Overshoot）、低于 GND 的负尖峰（**下冲**，Undershoot），或在边沿后来回振荡（**振铃**，Ringing）。

**I2C 中的典型特点**：在电阻上拉的总线上，上升沿通常较慢；主动拉低的**下降沿**更容易激发走线电感、寄生电容形成的振荡，产生下冲和振铃。明显的上升沿上冲也应检查探头接地、串扰、地弹、有源上拉以及引脚是否误配置为推挽输出，不能仅凭上冲判断引脚配置。

**常见原因**：

- 驱动器下降沿过快，例如 MCU 引脚被配置为高速、强驱动模式；
- 走线过长或通过排线、杜邦线连接，引入较大的寄生电感；
- 地回路不良，信号与地线之间形成较大的环路面积；
- 引脚被误配置为推挽输出（I2C 引脚必须为开漏模式）；
- **测量误差**：示波器探头使用长地线夹时，地线本身的电感会叠加出明显的振铃，实际信号可能并无问题。

**带来的危害**：

1. **误触发**：SCL 上的振铃若越过输入阈值且未被滤除，可能被识别为额外的时钟边沿，导致位错位、数据错乱；SDA 在 SCL 高电平期间的异常跳变则可能被识别为 START 或 STOP；
2. **器件应力与闩锁风险**：超出引脚允许范围的上冲、下冲可能使保护结构导通，产生注入电流，严重时损坏器件或引发闩锁（Latch-up）。允许幅度、持续时间和注入电流须以器件绝对最大额定值为准，不能统一按电源轨外 0.5 V 判断；
3. **EMI 增加**：快速边沿与振荡会增加电磁辐射。

规范为快速模式和快速模式增强的器件规定了输入端的**毛刺抑制**（脉宽 50 ns 以内的尖峰会被滤除），并对快速模式的下降时间设置了下限，以减轻这类问题；但标准模式器件不一定具备毛刺抑制能力。

**排查方法**：

1. **先排除测量误差**：换用短接地弹簧，探头尽量靠近被测器件引脚再测一次；
2. 检查引脚配置：确认 SCL、SDA 的输出类型及边沿速率配置符合当前 I2C 模式要求；
3. 观察振铃频率，结合走线长度判断是否为线路寄生参数引起。

**解决方法**：

1. **调整边沿速率**：若 MCU 支持 GPIO 速率控制，选择能满足当前模式下降时间要求的较低档位，并实测确认；不能对所有 STM32 型号和总线负载一律指定 Low。也可选用带下降沿速率控制的 I2C 器件；
2. **串联阻尼电阻**：在驱动端附近串联小电阻 Rs（通常为几十欧到一百多欧），抑制振铃。需要注意 Rs 会抬高低电平：VOL 会增加 IOL × Rs，阻值不宜过大；
3. **改善布线**：缩短走线，保证 SCL、SDA 下方有完整的地平面；使用线缆时，让 SCL、SDA 各自与一根地线绞合；
4. **适当并联小电容**：在信号线对地并联几十皮法的电容可以减缓边沿，但会增加总线电容、延长上升时间，需要与上一题一起权衡。

## Q: 什么是时钟拉伸（Clock Stretching）？

时钟拉伸是指**从机在 SCL 为低电平期间主动将其保持为低**，迫使主机等待，直到从机准备就绪后再释放 SCL。

它通常出现在从机需要额外时间处理数据的场景，例如作为从机的 MCU 需要在中断中准备数据，或部分传感器在测量完成前保持 SCL 为低（即"保持主机"的测量模式）。由于 SCL 同样为开漏线与结构，主机在释放 SCL 后需要检测其是否真正变为高电平，才能继续产生下一个时钟。

::: tip 注意区分
EEPROM 在内部写周期期间通常**不使用时钟拉伸**，而是对访问回复 NACK。驱动程序一般通过反复发送地址、直到收到 ACK 的方式（应答查询，Acknowledge Polling）判断写入是否完成。
:::

需要注意，并非所有主机都支持时钟拉伸，部分 MCU 的硬件 I2C 或软件模拟实现可能不检测 SCL 的实际电平，此时使用会拉伸时钟的从机可能出现通信异常。

## Q: 多个主机同时发起通信时，I2C 如何进行仲裁？

仲裁基于 SDA 的**线与**特性，在 SCL 为高电平时逐位进行：

1. 各主机发送数据的同时检测 SDA 上的实际电平；
2. 若某主机在参与仲裁的位上发送高电平（释放 SDA），却检测到 SDA 为低电平，该主机即**仲裁失败**，停止驱动 SDA；它可以继续产生时钟直到当前字节结束。若同时具备从机功能且获胜主机正寻址自己，则切换为从机响应；
3. 发送低电平的主机继续传输，且其数据未受任何破坏。

对于同时开始的普通 7 位寻址传输，若地址不同，数值较小的地址会在第一个不同位上胜出；若地址相同，仲裁还可继续到 R/W 位或后续位。因此总线并没有固定的主机优先级，普通接收方 ACK 拉低 SDA 也不等于主机仲裁失败。

仲裁还依赖 **SCL 时钟同步**：低电平由保持低电平最久的主机决定，高电平在最先拉低 SCL 的主机动作时结束。正常仲裁不会破坏获胜者的数据，但若仲裁尚未结束时一个主机发送 STOP/Sr、另一个仍发送数据，则属于规范未定义的组合，不能据此保证任意并发事务都安全。

## Q: 什么是 I2C 总线清除（Bus Clear）？为什么通常尝试 9 个时钟脉冲？

**总线清除**是 I2C 规范中定义的一种恢复手段，用于解决 **SDA 被从机持续拉低、总线无法使用** 的问题。

**问题成因**：主机在通信过程中被意外复位（或调试暂停使时钟停止），但从机没有复位，仍停留在传输中途。若此时从机正在输出数据位 `0` 或正在发送 ACK，就可能持续拉低 SDA。主机重新初始化后看到 SDA 为低，无法正常产生起始条件，总线因此"卡死"。

**恢复方法**：UM10204 §3.1.16 建议在 SDA 卡低时发送 **9 个时钟脉冲**；若仍未释放，则使用硬件复位或断电重启。恢复实现通常还会在能够控制 SDA 后发送 STOP，并验证总线空闲。每次释放 SCL 后都必须检测实际电平，不能把固定延时当作已经拉高。

**为什么是 9 个**：一个字节由 8 个数据位和 1 个应答位组成。对于仍能正常响应时钟、只是停在字节中途的从机，9 个脉冲可覆盖一个字节及其应答位置：

- 若从机正在**发送**数据：主机在恢复时释放 SDA，时钟推进到应答位时即构成 NACK，通知从机结束发送。
- 若从机正在**应答**：应答位结束后可能释放 SDA；后续行为还取决于它是在接收还是发送数据。

**9 个脉冲不是必然成功的保证**。SDA 在某个数据位变高也不一定代表事务已经结束，可能只是从机正在发送 `1`。若实现选择提前退出，需要结合 STOP 和总线状态验证；若器件状态机异常、线路短路或 SCL 无法拉高，应走复位或硬件排查流程。

**具体步骤**：

1. 确认没有正常事务进行，停用本机 I2C 外设，将 SCL、SDA 切换为 **GPIO 开漏输出**，初始状态均为释放；
2. 等待 SCL 实际变高，超时则退出；若此时 SDA 也为高且已确认总线空闲，则无需清除；
3. 保持 SDA 释放，发送 9 个 SCL 脉冲，每个高电平阶段均在读到 SCL 为高后开始计时；
4. 检查 SDA 是否释放，若仍为低则报告恢复失败；
5. 在 SCL 为低时拉低 SDA，释放 SCL 并确认其变高，满足 STOP 建立时间后释放 SDA；
6. 确认两根线都已变高，再由调用方恢复引脚复用并重新初始化 I2C 外设；失败时交由复位或故障处理流程。

```c
/* 平台需实现 GPIO 开漏操作、实际引脚读取与微秒延时。
 * scl_timeout_us 由器件和系统要求确定，I2C 没有通用的拉伸超时值。
 */
static int scl_release_wait_high(unsigned int scl_timeout_us)
{
    scl_release();
    while (!scl_read()) {
        if (scl_timeout_us == 0)
            return -2;                     /* SCL 无法拉高 */
        --scl_timeout_us;
        delay_us(1);
    }
    return 0;
}

/* 仅用于已排除其他主机活动的总线；调用前停用外设并配置 GPIO。
 * 5 us 延时用于标准模式恢复示意，还需结合实际边沿和平台开销验证。
 */
int i2c_bus_clear(unsigned int scl_timeout_us)
{
    sda_release();
    if (scl_release_wait_high(scl_timeout_us) != 0)
        return -2;
    delay_us(5);
    if (sda_read())
        return 0;                          /* 已确认空闲，无需恢复 */

    for (int i = 0; i < 9; i++) {
        scl_low();
        delay_us(5);
        if (scl_release_wait_high(scl_timeout_us) != 0)
            return -2;
        delay_us(5);                       /* 实际 SCL 高电平时间 */
    }

    if (!sda_read())
        return -1;                         /* SDA 仍低，需进一步恢复 */

    /* 先在 SCL 低时准备 SDA，避免意外产生 START */
    scl_low();
    delay_us(5);
    sda_low();
    delay_us(5);
    if (scl_release_wait_high(scl_timeout_us) != 0) {
        sda_release();
        return -2;
    }
    delay_us(5);                           /* STOP 建立时间 */
    sda_release();                         /* STOP */
    delay_us(5);                           /* 上升及总线空闲等待 */
    if (!scl_read())
        return -2;
    return sda_read() ? 0 : -1;
}
```

**注意事项**：

- 总线清除只能解决 **SDA** 被拉低的问题。若 **SCL** 被持续拉低，规范建议使用从机的硬件复位引脚，或对从机断电重启。
- 若 9 个脉冲后 SDA 仍为低，说明从机可能已异常，同样需要硬件复位或断电。
- 初始化或通信超时后应先判断是否确实卡死；多主机系统必须排除其他主机的正常传输和合法时钟拉伸，不能无条件发送恢复脉冲。恢复期间的时钟也可能被从机解释为数据，恢复完成后需按器件协议重新确认状态。
- Linux 提供 [`i2c_generic_scl_recovery()`](https://github.com/torvalds/linux/blob/master/drivers/i2c/i2c-core-base.c)。适配器驱动需配置 `struct i2c_bus_recovery_info`，包括恢复函数、SCL 控制与读取，以及按硬件需要提供 SDA、引脚复用切换等支持；仅填写 GPIO 并不保证恢复会自动触发。

## Q: 在 Linux 下如何扫描 I2C 总线上的设备？

使用 `i2c-tools` 工具包：

```bash
# 列出系统中的 I2C 总线
i2cdetect -l

# 扫描 1 号总线的默认地址范围 0x08 ~ 0x77
i2cdetect -y 1

# 以 SMBus Read Byte Data 读取 0x50 设备的命令/寄存器 0x00
# 仅适用于支持该事务格式的器件
i2cget -y 1 0x50 0x00

# 按默认 byte 模式遍历 0x00 ~ 0xff；需确认器件支持且允许这些读取
i2cdump -y 1 0x50
```

`i2cdetect` 的输出中，十六进制数字表示对应探测得到了应答；`UU` 表示该地址已被内核驱动占用，因此跳过探测；`--` 表示本次探测无应答，不能据此断定器件不存在。`-y` 表示跳过交互确认。

I2C 没有统一的设备发现命令，`i2cdetect` 使用 SMBus Quick Write / Receive Byte 进行探测，可能改变器件状态；扫描、读取和转储都应先确认芯片支持对应操作。`i2cdump` 不会自动理解寄存器映射，也不保证读出设备的全部存储空间。16 位内部地址等访问方式需要按器件协议构造事务，可使用 `i2ctransfer`。这些限制见 [i2cdetect 手册](https://kernel.googlesource.com/pub/scm/utils/i2c-tools/i2c-tools/+/master/tools/i2cdetect.8)、[i2cget 手册](https://kernel.googlesource.com/pub/scm/utils/i2c-tools/i2c-tools/+/refs/heads/master/tools/i2cget.8)和 [i2cdump 手册](https://kernel.googlesource.com/pub/scm/utils/i2c-tools/i2c-tools/+/master/tools/i2cdump.8)。
